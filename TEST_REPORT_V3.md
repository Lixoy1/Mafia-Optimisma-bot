Дата сборки: 2026-08-18

## Цель

Главный критерий v3: партия не должна оставаться навсегда в регистрации, ночи, номинации или голосовании даже при нуле действий, повторных callback'ах, конфликте таймеров, ошибках Telegram UI и перезапуске процесса.

## Что тесты уже поймали во время сборки

Тестирование не было формальным: оно обнаружило реальную ошибку ранней версии v3. `start_game()` логически оставался в REGISTRATION перед `start_night()`, из-за чего ночной переход мог не произойти/конфликтовать с автотаймером. Старт был перестроен через защищённый RESOLVING и добавлен отдельный regression test.

После этого обнаружен restart-risk: если persist сделать сразу после переключения REGISTRATION → RESOLVING, но до полной раздачи ролей, crash мог сохранить «полупартию». Порядок изменён: сначала фаза закрывается в памяти и назначается полный role pack, затем одним snapshot сохраняется восстановимое состояние. Для старых повреждённых snapshot'ов добавлен repair path.

## Ограничения текущей среды

В контейнере разработки не установлены реальные `aiogram` и `aiosqlite`, а внешняя установка пакетов недоступна. Поэтому core/smoke используют лёгкие offline stubs внешних библиотек.

Это означает:

- синтаксис и импорты проекта проверены;
- state machine и игровая логика проверены offline;
- сериализация GameState проверена;
- настоящий сетевой обмен Telegram Bot API здесь не выполнялся;
- настоящий SQLite через `aiosqlite` в этой среде не прогонялся;
- Railway restart с реальным Volume должен быть частью acceptance test.

## Обязательный live acceptance test

Перед приглашением большой группы:

- 4–8 реальных Telegram-аккаунтов;
- отдельная тестовая группа;
- Group Privacy disabled;
- бот администратор с Delete/Pin;
- каждый игрок нажал `/start` в ЛС;

- отдельно перезапустить Railway во время NIGHT и VERDICT;
- убедиться, что регистрационный закреп исчезает после старта;
- проверить, что старые inline-кнопки после переходов не воздействуют на текущую фазу;
- проверить FINISHED и возможность сразу запустить новую игру.

## Restart fuzz

Команда:

```bash
python tests/fuzz_restart.py
```

Результат финального прогона:

```text
RESTART FUZZ OK: 600 games, max_turns=32
```

В каждой партии движок случайно перезапускается из сохранённого snapshot на NIGHT, DISCUSSION, NOMINATION, VERDICT и RESOLVING. Используются все четыре режима. Часть ночей сохраняется с частично принятыми действиями, затем восстанавливается и продолжается.

## Баг, найденный этим прогоном и исправленный в 0.3.0a2

Fault-injection выявил опасный сценарий: если SQLite выбрасывал исключение при списании защитного предмета уже после начала `resolve_night()`, повтор таймера мог заново запустить расчёт по частично изменённому in-memory состоянию. В частности, одноразовое самолечение Хирурга могло считаться уже израсходованным.

В `GameEngine` добавлен локальный безопасный retry для операций `consume_item`. Временная ошибка SQLite больше не выбрасывает resolver из середины ночи и не меняет результат уже принятого действия.
