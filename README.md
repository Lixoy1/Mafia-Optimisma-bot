# Mafia Optimisma v3 — test build

Telegram-бот для групповой игры в «Мафию» с собственным оформлением Mafia Optimisma.

v3 перестроена вокруг жёсткого игрового автомата. Главная цель этой версии — устранить проблемы первого теста: вечное голосование, оставшиеся активные кнопки, потерянные таймеры и зависание игры после рестарта сервиса.

## Что уже реализовано

### Игровой цикл

Основная цепочка фаз:

```text
REGISTRATION
   ↓
NIGHT
   ↓
DISCUSSION
   ↓
NOMINATION
   ↓
VERDICT
   ↓
NIGHT или FINISHED
```

`RESOLVING` используется как короткое внутреннее состояние между фазами.

Каждая длительная фаза имеет deadline и guarded timer. Если обработка таймаута временно падает из-за Telegram/API-ошибки, движок не теряет единственный таймер: он логирует ошибку и повторяет завершение той же фазы.

### Регистрация как в хорошем игровом боте

- `/game` создаёт одну карточку регистрации.
- Карточка закрепляется в группе.
- В ней есть кнопка «Присоединиться».
- JOIN/LEAVE редактируют ту же карточку вместо создания новой карточки на каждого игрока.
- За 30 секунд до конца может появиться отдельное предупреждение.
- При закрытии регистрации сначала блокируется callback, затем карточка открепляется и удаляется.
- Ошибка удаления/открепления сообщения не имеет права остановить старт партии.

Правило интерфейса v3:

> Управляющий интерфейс исчезает, история партии остаётся.

### Ночь и день

- Ночь по умолчанию: 60 секунд.
- День/обсуждение: 45 секунд.
- Ночные действия выполняются в ЛС.
- После принятого действия группа может получить атмосферную фразу без раскрытия цели.
- Повторный финальный выбор в ту же ночь запрещён.
- Старые кнопки защищены `session_id` + номером дня/ночи.
- После ночи персональные кнопки отключаются.
- Живые игроки не могут писать ночью; сообщение удаляется, игрок получает уведомление в ЛС.
- Мёртвые не могут писать в игровую группу.
- Погибший получает одно «последнее слово» через ЛС, которое действует только до следующей ночи.

### Список живых

Публично показываются:

- стабильные номера игроков, выданные при регистрации;
- имена живых игроков;
- количество живых ролей каждого типа;
- общее число живых.

Роль конкретного живого игрока по этому списку не раскрывается.

### Двухэтапное голосование

1. `NOMINATION` — каждый живой доступный игрок выбирает кандидата или пропускает.
2. Если есть один лидер, запускается `VERDICT`.
3. На вердикте остальные доступные игроки выбирают 👍 Казнить / 👎 Помиловать.
4. Сам кандидат не голосует по собственной казни.
5. Заглушённые игроки не участвуют.
6. `Да > Нет` и хотя бы один голос «Да» → казнь.
7. Иначе кандидат помилован.
8. Если номинации нет или лидеры поделили максимум голосов — никто не казнён и запускается следующая ночь.

Даже при нуле голосов фаза заканчивается по таймеру и партия идёт дальше.

### Защита от зависаний

- Отдельный `phase_version` для каждой фазы.
- Один активный phase timer на игру.
- `asyncio.Lock` на чат защищает от двух одновременных завершений фазы.
- Ручной `/start` и автозапуск регистрации не могут дважды раздать роли.
- Старые callbacks не могут воздействовать на новую ночь/партию.
- `finish_game()` идемпотентен.
- Telegram-ошибка при send/edit/delete/unpin не должна останавливать state machine.

### Восстановление после Railway restart

Активная партия сохраняется в SQLite (`game_sessions`) вместе с:

- `session_id`;
- фазой и `phase_version`;
- deadline;
- игроками и стабильными номерами;
- текущими и начальными ролями;
- ночными действиями;
- номинациями и вердиктами;
- важными message IDs;
- правом последнего слова;
- состоянием специальных ролей.

После запуска бот читает незавершённые партии:

- если deadline ещё впереди — восстанавливает таймер на оставшееся время;
- если deadline прошёл — сразу пытается завершить фазу;
- старый неполный `RESOLVING`-снимок без ролей автоматически ремонтируется перед продолжением.

Для Railway поэтому **обязательно нужен Volume**.

## Режимы

- `/game` или `/game1` — 🏙 Городской оптимизм
- `/game2` — 🌪 Весёлый хаос
- `/game3` — 🧟 Эпидемия улыбок
- `/game4` — 🌸 Война улыбчивых кланов

Один Game Engine используется разными ruleset'ами.

### Городской оптимизм

Минимум 4 игрока. Для 4 игроков базовый набор:

- 🤵🏻 Карлеоне ×1
- 🩺 Хирург ×1
- 🙂 Оптимист ×2

Ищейка появляется с 6 игроков, затем добавляются расширенные роли.

### Весёлый хаос

Более высокая плотность активных ролей и мафия примерно в пропорции 1:3. В этом режиме для Семьи разрешён friendly fire. Ищейка может стрелять с первой ночи. Пока жив Потрошитель, уничтожение Семьи само по себе не завершает игру победой города.

## Роли

В сборке есть собственные роли Mafia Optimisma:

🙂 Оптимист, 🤵🏻 Карлеоне, 🕴 Торпеда, 🩺 Хирург, 🕵️ Ищейка, 🪦 Фаталист, 🧥 Ночной Бродяга, 💋 Ночная Дива, 💻 Взломщик, 🛡 Живой Щит, 💣 Подрывник, 🕶 Тень, 👮 Стажёр, 🍀 Счастливчик, 🔪 Потрошитель, 👩‍⚕️ Сестра Милосердия, 🗞 Досье-Мейкер, ⚖️ Мастер Алиби, 🐺 Перевёртыш, 🃏 Джокер, 🧟 Носитель, 👹 Император Сакуры, 🎴 Самурай, 💪 Костолом, 🥷 Синоби, 🎭 Фальсификатор.

Ключевые взаимодействия, уже покрытые движком/тестами:

- блокировка отменяет ночное действие;
- лечение может снять дневное последствие Ночной Дивы;
- Хирург может лечить себя один раз за игру;
- несколько убийц могут атаковать одну цель в одну ночь;
- Перевёртыш превращается от определённых визитов, а соответствующий смертельный удар поглощается превращением;
- Стажёр/Сестра видят действия наставника и наследуют роль;
- Карлеоне/Император наследуются бойцами своего клана;
- проверяемая цель получает уведомление, что её ролью кто-то интересовался;
- союзники Семьи/Сакуры могут общаться через ЛС бота ночью.

## Экономика

Профили и предметы находятся в SQLite.

В текущем test build денежная награда за победу включается только от `MIN_REWARD_PLAYERS` (по умолчанию 6). Победителю начисляется 20 💵; маленькие тестовые партии статистику записывают, но деньги не фармят.

В критическом игровом пути **нет Groq/LLM/API генерации текста**. Внешний AI не может остановить партию.

```bash

pip install -r requirements.txt
cp .env.example .env
python -m compileall mafia_optimisma run.py

```

В логах успешного старта:

```text
Mafia Optimisma started as @...; restored games=...
```

## GitHub + Railway

1. Создай пустой GitHub-репозиторий, например `mafia-optimisma-bot`.
2. Из корня проекта:

```bash
git init
git add .
git commit -m "Mafia Optimisma v3"
git branch -M main
git remote add origin https://github.com/USERNAME/mafia-optimisma-bot.git
git push -u origin main
```

3. В Railway создай Project → Deploy from GitHub Repo.
4. Выбери репозиторий.
5. Добавь Variables из раздела выше.
6. Добавь Railway Volume с mount path:

```text
/data
```

7. Деплой запускается командой `python run.py` из `railway.json`.
8. Используется long polling. При старте бот делает `delete_webhook()`, чтобы старый webhook не блокировал polling.

## Telegram / BotFather

Для игровой группы:

1. Открой ЛС бота и нажми `/start` каждым игровым аккаунтом.
2. В BotFather отключи Group Privacy (`/setprivacy` → Disable) для игрового бота.
3. Добавь бота в группу.
4. Дай права, необходимые для механики группы, прежде всего удаление сообщений и закрепление сообщений.

Каждый игрок должен открыть ЛС хотя бы один раз: Telegram не позволяет боту произвольно первым начать диалог с пользователем.

## Что ещё считаем тестовым

Это уже существенно более надёжное ядро, но пока не называем его окончательно production-validated, потому что в текущей среде не было живой Telegram/Railway партии с реальными аккаунтами.

Перед массовым запуском нужно пройти реальный acceptance test минимум на 4–8 аккаунтах:

1. `/game` → карточка закрепилась.
2. JOIN обновляет одну карточку.
3. `/extend` реально добавляет 30 секунд.
4. Старт → кнопка отключилась, карточка открепилась и исчезла.
5. Все получили роли в ЛС.
6. Ночь закрылась по таймеру даже при пропущенных действиях.
7. День дошёл до NOMINATION.
8. NOMINATION с нулём голосов не завис.
9. NOMINATION с кандидатом перешёл в отдельный VERDICT.
10. VERDICT всегда завершился.
11. Старые кнопки после перехода не работают.
12. Рестарт Railway посреди NIGHT и VERDICT продолжает партию.
13. Победа приводит к FINISHED, наградам и полной очистке активной игры.

Из известных механик, которые ещё требуют отдельной полировки по реальным партиям: точный момент мести Подрывника (сейчас короткая переходная sub-phase после казни) и некоторые редкие приоритеты пересечения продвинутых ролей.
